05 · Initial API contract proposal

Agree these routes with the backend owner. They are proposals, not existing endpoints.

MethodEndpointPurposePriority
GET/api/v1/healthConfirm API reachableFirst
POST/api/v1/auth/otp/requestRequest OTP for phone numberCore
POST/api/v1/auth/otp/verifyVerify OTP and establish sessionCore
GET/api/v1/users/meRead authenticated profileIf needed
PATCH/api/v1/users/meSave first and last nameCore
POST/api/v1/auth/googleOptional Google credential exchange/verificationOptional
Security: Never store OTPs or secrets in plaintext, commit credentials, or treat a UI-only OTP as real authentication. Use an explicitly labelled development simulation until provider and security requirements are confirmed.
